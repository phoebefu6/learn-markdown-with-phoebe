# Presenter notes - Session 1 · First words

Audience: total beginners. Assume zero exposure - some have never heard the word "markdown".
Energy goal: "oh, I can already do this" by minute 25.

## Preflight (10 min before)

- [ ] stackedit.io/app open in a clean tab, sample text cleared, font zoomed for projector
- [ ] dillinger.io open in a backup tab (stackedit occasionally hiccups on hotel wifi)
- [ ] Session 1 page open, Projector zoom: 125% toggled
- [ ] One AI chat tab (any assistant) with a formatted answer ready - the Part 1 "you've seen this" reveal
- [ ] Your own about-me draft from a dry run - the "here's mine" moment for Demo 2
- [ ] Wifi fallback: markdown works offline in any notes app - worst case, type in TextEdit and narrate the rendering

## Run of show

| Minute | Beat | Notes |
|---|---|---|
| 0-3 | Welcome + the promise | "By Session 4 your page is live on the internet." Show YOUR live profile if you have one - 10 seconds, no tour. |
| 3-9 | Part 1: what markdown is | Pipeline SVG. The AI-chat reveal is the hook: pull up the prepared chat, point at headings/bullets - "that's markdown, you've been reading it for years". |
| 9-11 | Part 1: history story | 2 min max. Gruber 2004, readable-as-plain-text goal. Story voice, not lecture voice. |
| 11-15 | Part 2: headings + paragraphs | rawpair figures on screen. Type #Heading live WITHOUT the space first - let them see it fail, then fix. Failure-first sticks. |
| 15-18 | Part 3: emphasis, lists, links | Speed round. "Square brackets say it, round brackets take you there" - make them repeat it out loud, it's silly, it works. |
| 18-24 | Demo 1: first typing | Everyone in stackedit. Walk the room (or breakout rooms). Nobody left behind here - this demo gates everything. |
| 24-36 | Demo 2: about-me draft | The heart of the session. Announce the Session 4 stakes again mid-demo: "someone WILL read this". |
| 36-40 | Demo 3: break it on purpose | Fast, playful. Frame as "meeting every bug in captivity". |
| 40-45 | Q&A + homework + quiz pitch | Point at the quiz on the page - "do it before you close the tab". |

## Never cut

1. The AI-chat markdown reveal (Part 1) - it reframes markdown from "new thing" to "thing you already know".
2. #Heading space-fail live demo - the most common bug, best taught by failure.
3. Demo 2 discernment lap ("read the right pane like a stranger") - ownership moment, quality of their final page depends on it.
4. The Session 4 stakes line - the running project is the retention engine.

## Cut if long

- History card detail (compress to one sentence: "one guy, 2004, wanted text you could read raw - it won").
- Demo 3 step 4 (indent-makes-code-box) - it reappears in Session 2 code blocks anyway.
- Part 1 third bullet round (future-proof/fast) - the everywhere argument alone carries.

## Parking lot (likely questions, ready answers)

- "Can I use Word instead?" - Word is fine for Word things; markdown is for the web, GitHub, notes apps, and AI. Different tool, and this one is free and 45 minutes from mastered.
- "Why not just use Notion's buttons?" - Notion's buttons ARE writing markdown for you; type # + space in Notion and watch. Learning the syntax makes you faster in every tool at once.
- "Do I need to code?" - No. Markdown is text formatting, not programming. If you can type an email you're fully equipped.
- "My two spaces line break isn't working" - most likely the editor trims trailing spaces; use <br> and move on, revisit in Session 2.
- "Is this the same as HTML?" - Markdown becomes HTML behind the scenes. You write the friendly version, the processor writes the tags.
